# Public Execution Projection

Date: 2026-09-09
Implemented: 2026-09-14

## Problem

An API key holding `EXECUTE_REPOSITORY` but not `READ_PRIVATE` may run commands against a workspace, yet the only execution copy that existed was the complete repository bundle with original ancestry. Filtering that bundle cannot make it safe: private files, private frontmatter, source `AGENTS.md` guides, commit identities, authors and configuration remain recoverable through Git history, and any path or link that names private content leaks the fact of its existence.

The public reader therefore needs a separate reading namespace derived solely from approved publication, a way to tell when that namespace is stale without exposing the private authority commit, and a session lifecycle that does not enlarge, downgrade or silently rebuild a copy while a command is running. [CodeAct content and media](2026-09-09-codeact-content-and-media.md) owns the repository format, media bridge, authoring, exports and migration; this record owns how the public projection is built, validated and withdrawn.

## Decision

This record was consolidated on 2026-09-17 after the work shipped under the notes it names. The core mechanism arrived on 2026-09-10 with the scoped CodeAct workspaces change; the remaining delivery items closed on 2026-09-14 under [workspace website delivery](2026-09-14-workspace-public-delivery.md) and [account working copies](2026-09-14-account-working-copies.md).

**Scope selection.** A session opened with `READ_PRIVATE` exports the complete repository bundle with original ancestry. Without it, `RepositorySnapshotExports.createPublic` builds a fresh bare Git repository in the configured staging directory from the current approved publication snapshot and exports one parentless commit on `refs/heads/snapshot`. A public open that names a commit is refused; public execution starts from current publication only.

**Bundle contents.** The generated commit carries a fixed service identity (`Poketto <poketto@invalid>`, epoch timestamp, UTC) and the message `Public reading projection`, so equal projections hash equally. Original repository objects, commit identities, authors, configuration, private files and arbitrary frontmatter never enter the bundle. Each article becomes a frontmatter block of `title`, `tags`, `route`, `public_author` and, when present, `date` and `updated_at`, followed by the sanitized Markdown body. [Public author names](2026-09-14-public-author-names.md) owns the explicit signature field. Source `AGENTS.md` files are dropped and a service-owned root `AGENTS.md` guide explains the projection's limits to the agent.

**Body sanitization.** HTML blocks, inline HTML and link reference definitions are removed. Links and images to approved articles or admitted indexed media are rewritten to relative projection paths. A destination that does not resolve, or resolves to private content, is flattened to its plain text. Own-page fragments and absolute `http`, `https` and `mailto` destinations are kept as authored and never fetched. Traversal is bounded to 20 000 nodes and depth 128; each article stays within the document byte limit and the projection within a workspace byte bound.

**Route mapping.** Each public route maps to a folder holding `index.md`; the root route is root `index.md`. A route segment named `index.md`, `AGENTS.md` or `.poketto`, or beginning with `~`, gains a `~` prefix so the mapping stays injective and no projected file becomes a directory of another. Two routes normalizing to the same path, or nesting, reject the whole projection. The original source paths stay in a host-only mapping inside `PublicExport.sourcePaths`.

**Media.** Media referenced by an approved article and permitted by the publishing policy receives a logical alias `N-<basename>` below a `_media` folder (or `_media_N` when a route already claims that prefix), and the projection writes an approved `.poketto/assets.json` listing those aliases. Originals are not eagerly copied; `poketto media fetch` in a public session resolves only through the host-owned mapping, as the [worker reference](../../executor-service/README.md) describes. An absent local media file is not a deletion.

**Validity without exposing the authority commit.** `PublicExecutionProjection.fingerprint` hashes length-delimited projected files, source mappings and media aliases with SHA-256. `JGitRepositorySnapshotExports` keeps a bounded, access-ordered cache of 64 fingerprints keyed by workspace and immutable authority commit; the cache holds hashes, never source text. `requireCurrentPublic` authorizes `EXECUTE_REPOSITORY`, rejects a proof from another workspace even when the content would be identical, obtains the current unexpired publication snapshot, compares its fingerprint with `PublicExport.projectionSha256`, then re-authorizes and checks that the snapshot commit has not moved in the meantime. Private-only commits therefore leave a public session valid; a changed public article, changed source mapping, disabled publication or failed authorization invalidates it.

**Session lifecycle.** The session keeps the scope selected when it opens. Gaining `READ_PRIVATE` later does not enlarge an existing public copy, and an explicit copy ID retains its reading scope, as [account working copies](2026-09-14-account-working-copies.md) records. `SessionWorker.authorize` routes every check for a public session through `requireCurrentPublic`; `IsolatedRepositoryExecutor` performs that check before opening, before each command, after a completed command before its output is returned, before artifact reads and bridge replies, and on each lease renewal. The existing worker close protocol terminates an invalid lease. A command may finish locally while publication is withdrawn; its output is then suppressed. The host never replaces local files during a command: a changed publication requires a new session, which obtains the replacement projection.

**Export bounds and cleanup.** Projection export runs under the configured bundle byte limit and wall-time limit shared with full exports, in a fresh disposable `<id>.projection` directory with private permissions. After object writing and bundle creation the export re-authorizes and re-reads the snapshot; a withdrawal during export leaves no bundle and no projection. Cleanup refuses paths outside the staging directory, refuses to follow symlinks, and clears the read-only flag JGit sets on loose objects so Windows can delete them.

This mechanism limits the data available to a public key. It does not infer user intent and does not prevent a fully authorized external harness from following injected instructions. Already delivered data cannot be recalled.

## Alternatives

**Filtering an original clone.** Rejected: private objects remain recoverable through Git history, and the current tree cannot be made safe by path filtering alone. The projection is built from publication fields, never from the source tree.

**Pinning validity to every source commit.** Rejected: it would close public sessions after each unrelated private edit. Comparing the fingerprint of the approved projection keeps the session alive across private-only commits while still catching every public change.

**Rebuilding the working tree in place when publication changes.** Rejected: it would discard local analysis and change command semantics mid-session. A changed publication expires the session and a new one obtains the replacement.

**Treating a fingerprint as authorization.** Rejected: the cache accelerates comparison only. Every check still obtains a current publication snapshot and re-authorizes the principal, so a cached hash cannot substitute for current authorization.

## Consequences

- A public-only key can run commands, read, search and export, but sees only what the website may already serve. `docs/usage.md` states that public-only sessions receive a fresh current-public projection without original history or private metadata, always export the host-approved public projection, cannot save, and report `PUBLIC_PROJECTION` with a synthetic commit from `poketto status`.
- Public and full projections are separate copies; one account's authorized clients share a copy only within the same workspace and reading scope.
- Every public command pays for a fingerprint lookup; a cache miss recomputes the projection within the export deadline, which bounds the cost of a large publication.
- Route segments that collide with reserved names are visibly renamed with `~`; agents reading the projection must not assume projected paths equal repository paths.
- Withdrawal is not instantaneous for bytes already in flight; the guarantee is that no further output is returned after the check fails.
- The projection rejects, rather than partially serves, a workspace whose routes collide or nest or whose size exceeds its bounds.

## Implementation and acceptance

Classes: [`PublicExecutionProjection`](../../src/main/java/io/github/core607/poketto/content/internal/PublicExecutionProjection.java) builds the projection, computes the fingerprint and owns the route, media and sanitization rules; [`JGitRepositorySnapshotExports`](../../src/main/java/io/github/core607/poketto/content/internal/JGitRepositorySnapshotExports.java) implements `createPublic`, `requireCurrentPublic`, the fingerprint cache, the parentless commit and cleanup; [`RepositorySnapshotExports`](../../src/main/java/io/github/core607/poketto/content/RepositorySnapshotExports.java) declares the `PublicExport` and `PublicMedia` records; [`SessionWorker`](../../src/main/java/io/github/core607/poketto/executor/internal/SessionWorker.java) selects the public check for non-full-read sessions and [`IsolatedRepositoryExecutor`](../../src/main/java/io/github/core607/poketto/executor/internal/IsolatedRepositoryExecutor.java) calls it at the lifecycle points above and refuses a requested commit for a public open. The projection class was split out of the export wrapper on 2026-09-16 without changing behavior.

Real Git fixtures in `RepositorySnapshotExportsTests` prove one independent commit containing only approved fields, denial before snapshot or repository access, no bundle or projection after withdrawal during export, validity across private-only commits with rejection of changed publication and of other workspaces, and README-only folder link resolution. Real socket tests in `WorkerSocketTests` prove that public readers open only the projection and can neither select source history nor silently upgrade, and that a withdrawn projection suppresses completed output and closes the lease.

The [native projection run](../../executor-native/evidence/2026-09-10-public-projection.json) connects a synthetic Git authority through the production publication and export services, Java adapter, root worker and SRT on Linux. It records passes for a projection with no private files, metadata or original history; no expansion of an existing public copy after a permission increase; denial of further output after withdrawal; and public media fetch through the host-owned mapping only. Its authentication is a stub; it does not replace PostgreSQL or real HTTP MCP client acceptance. The same file records one unrelated failure in an adapter session-reuse scenario, traced to a bridge-poll shutdown defect and fixed with a deterministic regression test; the projection assertions and cleanup passed. The [executor-native reference](../../executor-native/README.md) describes the scenario.

The three items the proposal left open are closed by later records: the [native member-media run](../../executor-native/evidence/2026-09-14-member-projection-media.json) exercises actual CLI media fetches through the projection mapping while website delivery is disabled, including local index tampering and withdrawal, under [workspace website delivery](2026-09-14-workspace-public-delivery.md); the [authenticated HTTP evidence](../../acceptance/clients/evidence/2026-09-14-account-copies.json) includes a scenario in which a public copy keeps its scope when accessed by a full grant, under [account working copies](2026-09-14-account-working-copies.md); and [`docs/usage.md`](../../docs/usage.md) documents public-only sessions, exports and status. Gallery materialization inside the projection is not claimed: the root guide states that listed originals are not materialized there.
