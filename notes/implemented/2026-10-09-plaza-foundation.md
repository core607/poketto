# Public plaza authority and account state

Date: 2026-10-09

## Problem

The repository MCP entrance addresses one authorized workspace. Cross-space public
discovery needs neither private repository files nor a shell, while private notes
for a later agent session need an owner independent of any one workspace or
transport. A workspace key manager is not that account's personal delegate.

## Decision

`wander` is one application-interpreted action entrance. It dispatches fixed
platform operations without an executor lease. Public reading uses the enabled
space catalogue and verified current snapshots; bounded scans either account for
the complete catalogue or refuse. They do not materialize remote repositories.
Public presentation fields and canonical article links form the output contract;
raw source paths and Git history do not.

Private pocket notes and discovery state belong to the account. The credential
holder grants access through a browser session, independently of workspace key
issuance. Each operation rechecks the credential, membership, creator eligibility
and current personal grant. Account locking orders these operations with identity
and policy changes. Notes carry request identities; deletion clears text but keeps
a bounded receipt so replay cannot resurrect a removed note.

The world provides short descriptions and useful continuations; help exposes every
action and actual lock. Mystery belongs to discoverable material, not syntax or
permission puzzles. MCP structured status and the last text line are generated by
the adapter, outside untrusted content. Client names are self-reported decoration,
never identity or authorization evidence. [Usage](../../docs/plaza.md) owns syntax,
limits and configuration.

This partially supersedes the worker-only public text restriction in the
[CodeAct entrance](2026-09-10-codeact-mcp-entrance.md), not its private file or write
boundary. The [public search](2026-09-14-public-site-search.md),
[website delivery](2026-09-14-workspace-public-delivery.md),
[consumer identity](2026-09-20-consumer-identity-and-site-policy.md) and
[community](2026-09-23-community-interactions.md) records retain their respective
authority. Candy, comments, games and QA remain in the
[plaza proposal](../proposed/2026-10-09-plaza-exploration.md).

## Alternatives

A shell for discovery consumes creation capacity and exposes state that public
reading does not need. One tool per action loses the common discoverable entrance.
Full corpus materialization adds storage and withdrawal coordination without a
measured need. Automatically extending workspace keys delegates personal account
data to a different authority, so consent is separate.

## Consequences

Ordinary exploration does not consume worker sessions. PostgreSQL retains private
account state rather than an article projection. Reading still depends on complete,
valid snapshots; measured capacity can justify an incremental lexical index, and
semantic misses can justify embeddings. This choice establishes no superiority over
conventional RAG. Withdrawal affects subsequent operations, not already delivered
copies. Bounded receipt retention can refuse further notes when exhausted.

## Verification

`PlazaCommandTests`, `PublicPlazaReadsTests`, `PlazaMcpToolTests`,
`PlazaIntegrationIT` and `McpProtocolIntegrationIT` pin the parser, public delivery,
wire status, personal grants and durable state. The account grant component test
and isolated browser entrance cover the human consent surface.
