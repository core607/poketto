# Repository-Native Retrieval and Sandboxed Agent Execution

Date: 2026-09-01
Implemented: 2026-09-10

## Problem

The [requirements](2026-08-25-requirements-and-architecture.md) originally put document search in a PostgreSQL `search_documents` projection and gave AI agents a fixed set of retrieval tools. That design kept queries predictable, but it made PostgreSQL duplicate repository content, added replay and checkpoint state, and limited an agent to query shapes implemented in advance.

Poketto instead needs trusted agents to inspect the repository as a repository: Git history, exact text search, frontmatter inspection and short programs, combined freely, without access to the live content worktree or the host. Public pages still need bounded read interfaces that cannot turn a public request into command execution. Running model-produced code inside the Spring process is not a security boundary: the JDK [permanently disables the Security Manager from JDK 24](https://docs.oracle.com/en/java/javase/25/security/security-manager-is-permanently-disabled.html), and an embedded language that exposes only selected APIs reproduces a fixed tool surface rather than providing ordinary repository tools.

## Decision

The notes linked below own their parts; where the shipped design departs from the proposal, this section says so.

**No content index in PostgreSQL.** PostgreSQL holds relational application state only: workspaces, accounts, memberships, invitations, key metadata, audits and the space catalog. The projection and search modules, `search_documents`, zhparser and the custom database image were removed; [stock PostgreSQL](2026-09-05-stock-postgresql.md) records that removal and reserves no projection or tokenizer. Every repository read resolves a workspace and a committed remote `main` revision through [remote repository authority](2026-09-01-remote-repository-authority.md) and observes that commit for the whole request. Public rendering and administration read a validated committed tree through workspace-scoped contracts ([repository authoring foundations](2026-09-05-repository-authoring-foundations.md)); public callers select no visibility scope and reach no executor. Search over the repository is a bounded scan of the selected commit with no durable index: [administration filename search](2026-09-14-administration-filename-search.md) and [public site search](2026-09-14-public-site-search.md) refuse rather than sample when a bound is exceeded. A persistent index still requires its own decision with measured need.

**`repo_exec` is the agent's repository entrance.** The [CodeAct MCP entrance](2026-09-10-codeact-mcp-entrance.md) owns the tool catalog: `repo_exec` runs shell, Python, Git, listings and search inside an isolated copy, `get_artifact` reads bounded command output, `repo_discard` releases a copy, and `get_asset` and `put_asset` carry images ([MCP image transfers](2026-09-15-mcp-image-transfers.md)). The structured `get_file` read and the `repo_patch` write bridge this proposal defined were removed without a compatibility alias: an agent reads files with ordinary tools in the copy and saves selected files through the CLI bridge, whose acknowledged saves are the only path back to authority ([CodeAct content and media](2026-09-09-codeact-content-and-media.md), [mutable working copy baselines](2026-09-15-mutable-working-copy-baselines.md)). A completed command therefore never acknowledges a content write. Execution requires the separately grantable `EXECUTE_REPOSITORY` capability; with `READ_PRIVATE` the copy holds the full repository with history, without it the copy is the [public execution projection](2026-09-09-public-execution-projection.md), never a filtered clone.

**Copies belong to accounts, not sessions.** The proposal's per-session, commit-pinned workspace became one retained copy per account, workspace and reading scope on a quota-enforced XFS pool, with leases, expiry, serialization and copy identity owned by [account working copies](2026-09-14-account-working-copies.md), and the copy's local Git view by [mutable working copy baselines](2026-09-15-mutable-working-copy-baselines.md) and [whole-workspace synchronization](2026-09-15-workspace-synchronization.md). Local changes inside a copy never reach workspace `main`; only a selected save does.

**The sandbox boundary shipped as proposed.** A root supervisor, the executor-service worker described by [local execution supervisor](2026-09-05-local-execution-supervisor.md), receives signed leases over a permissioned local socket and runs every command through the pinned Anthropic Sandbox Runtime launcher as a separate unprivileged account, inside one systemd transient unit per lease ([per-lease command sandboxes](2026-09-16-per-lease-command-sandboxes.md)) with bwrap and seccomp confinement. Spring passes an opaque lease derived from the authorized workspace and verified commit; no caller supplies a repository URL, cache path or host path. Commands see the copy, the declared [sandbox toolkit](2026-09-05-local-execution-supervisor.md#sandbox-toolkit) and the unit's private temporary storage; the application cache, other copies, managed originals, configuration, credentials and sockets are inaccessible; network access is denied; time, memory, process count, storage and output are bounded outside the command; and a sandbox setup failure rejects the command with no direct-process fallback. The Spring container holds no Docker socket, broad mount or elevated capability.

**Measured, not assumed.** The proposal required a low-spec exercise; the [real-corpus worker sample](../../acceptance/evidence/2026-09-15-real-corpus-worker-timing.json) records an initial open of a 173 MB retained bundle and twenty reused native executions at about 0.55 s each on the isolated pool. Every tool call leaves one outcome record without arguments, commands or paths ([service diagnostics](2026-09-14-service-diagnostics.md)).

## Alternatives

**Keep PostgreSQL full-text search as the default AI path.** Efficient for repeated ranked queries and Chinese tokenization, but it duplicates content and metadata, needs replay and freshness contracts, and leaves repository structure and history outside the agent's normal read surface. It lost, and stock PostgreSQL removed it.

**Expose only fixed MCP retrieval tools.** Easy to authorize and cheap to run, but every new investigation becomes server code. Bounded read APIs remain the public and browser path; agents compose ordinary tools inside a copy.

**Embed a restricted JVM language.** Starlark, Painless-style allowlists or a Groovy sandbox can expose safe domain APIs cheaply, but cannot provide ordinary Git, ripgrep, shell and Python without recreating an operating-system capability surface inside the JVM. This guard stands: nothing model-produced runs in the Spring process.

**Run every command in an OCI container or gVisor sandbox.** A stronger boundary and the fallback for a multi-user or hostile-code service; its image lifecycle and resident runtime were not justified for the single-host deployment, and the Sandbox Runtime boundary held in the real topology. Remote workers were part of the [optional serverless profile](../rejected/2026-09-01-optional-serverless-deployment-profile.md), which is rejected; a replicated or serverless deployment needs a new proposal.

**Execute against the live repository read-only.** Avoids the copy, but tools create locks and caches, a policy error exposes authoritative state, and a long read races advancing history. A copy gives commands a coherent baseline and makes local mutation irrelevant to authority.

## Consequences

Repository scans cost linear time and exact search ranks less well than the planned tokenized index; the bounds refuse instead of sampling, and a personal corpus has stayed within them. Copies occupy quota-accounted disk and are retained across sessions, which trades the proposal's per-session cleanup for a lease and expiry model. The sandbox is a same-kernel boundary: patching the host and the pinned runtime remains an operational duty, and resource limits bound denial of service without replacing that. The audit of a command names its identity and outcome, never its bytes.

## Implementation and acceptance

`EXECUTE_REPOSITORY` is a value of `Capability` in the `auth` package, and the worker's confinement is in `executor-service/worker.py`. The verification sections of the [local execution supervisor](2026-09-05-local-execution-supervisor.md) and [account working copies](2026-09-14-account-working-copies.md) name the socket, worker and native probe tests. [Repository directory navigation](2026-09-08-repository-directory-navigation.md) keeps the browser listing; its MCP listing tool was removed with the [CodeAct MCP entrance](2026-09-10-codeact-mcp-entrance.md).
