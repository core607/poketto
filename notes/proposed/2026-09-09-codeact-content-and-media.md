## Repository and media

The default content repository has root `AGENTS.md`, `public/` and `private/`. Both content trees use ordinary independently chosen categories; mirrored directories and duplicate documents are not required. New content is private unless publication is requested. Only eligible content below the exact root `public/` can be published. The publication enable switch and exclusions remain; exclusions win. Other paths, guides, internal metadata and unsafe files remain private. Default public routes omit the `public/` prefix; explicit routes do not grant publication rights.

Images, audio, video, PDFs and other downloadable files use one local immutable BlobStore. Git's `.poketto/assets.json` is a versioned mapping from logical path to opaque asset identity, immutable revision, size and media type. Markdown uses relative paths. The application validates and serializes index changes together with text edits, after original bytes are durably stored. Replacements create new originals; historical references remain readable. No acknowledged original is garbage-collected by this delivery.

Deduplication is strictly keyed by workspace and byte digest. Equal bytes in different workspaces never share a physical object, identity, upload result or reference count. Within a workspace, physical byte reuse never merges logical-path authorization. Blob objects have no global public flag. Delivery binds workspace, logical reference, exact version and current publication state. Storage, idempotency, hashes, caches, quotas, exports and diagnostics all retain workspace scope; hashes are not bearer credentials or a cross-workspace existence oracle.

Originals remain local; an OSS adapter is not part of this delivery. Ordinary files default to a configurable 128 MiB upload bound with streaming I/O. Image preview retains the existing 16 MiB and decoded-dimension limits. Non-image files are authorized downloads, not inline active content. The browser combines Git entries with media-index paths into one file tree. Source metadata, runtime placeholders and blob coordinates must not masquerade as actual media bytes.

## CodeAct and security

`repo_exec` is the primary agent file entrance. The declared environment supplies shell, Python, search and a precise patch command. All authorized current text is present at session admission; media paths are discoverable through the index and CLI, and originals materialize on demand as actual files within the session quota. Missing local media is not an empty placeholder and never implies deletion. Exceeding preparation limits fails explicitly rather than returning an incomplete full-text workspace.

Full-read sessions retain independently copied original Git history. Historical media is fetched through the exact historical index revision, subject to current full-read authorization. Public-only sessions contain only the currently valid public projection and approved media mapping, with a fresh local baseline and no original objects, history, private frontmatter or metadata. Every session remains bound to identity, workspace, scope, base and a bounded lease. Revocation and affected publication withdrawal invalidate execution, outputs and bridge handles; already delivered client data cannot be recalled.

A small `poketto` CLI provides media list/fetch/import, move, status, selected-file commit and export. Credentials remain outside the sandbox. A bounded host bridge reuses domain authorization; no application control socket, original store, authority cache or generic outbound network is exposed to commands. Runtime initialization fails closed. Logs, images, files, concurrent execution, time and temporary storage remain bounded and session-scoped.

There is no mandatory server-side reviewer model or manual approval workflow. External harnesses own user-intent interpretation and prompt-injection defenses. Poketto owns deterministic capabilities, workspace containment, public eligibility, asset ownership and atomic persistence. A client-supplied task description is not proof of user authorization. An agent with both private-read and publish capabilities can misuse those legitimate powers; neither this service nor its sandbox claims to prevent every such misuse or to control other tools in an external harness.

## Saving, moving and exporting

Saving captures selected files and explicit deletions from a stable execution snapshot. The service owns the baseline and revisions, validates all bytes and assets, and commits the complete text/index candidate through the shared remote-ref writer. Check `PUBLISH` for changes to existing or newly public content, assets, galleries, routes or policy, not only private-to-public moves. Local process success and local Git commits do not acknowledge remote saves. Conflicts preserve local work; uncertain acknowledgements reconcile before retry. Successful saves advance the session baseline while retaining unselected edits. Ordinary session expiry or restart can discard unsaved work.

Browser file/folder moves use a destination folder picker and the same move service as the CLI. Public/private switches move the selected content between the two roots, preserving its category path unless another destination is selected. Directory moves include indexed media without requiring their bytes to be fetched. File moves do not silently relocate shared dependencies. Repair resolvable Markdown links and index paths in one authorized candidate; refuse collisions, missing write permissions and newly invalid public/private references. Plain shell moves remain available, but dependency repair requires the CLI or agent edits. Publicly referenced bytes cannot be made secret by retaining another private reference to them.

Browser and CLI content exports produce portable ZIPs containing selected documents and actual required media with package-relative links. Private exports require read authority; public-share exports include only currently public content and reject private selections instead of publishing them. Do not recursively follow article hyperlinks or fetch external URLs. Exclude original Git history, credentials, internal index and physical storage coordinates. Missing originals, unauthorized dependencies or exceeded bounds fail the export rather than claiming completeness. Default bounds are 512 MiB of originals, 10,000 entries and one concurrent export per instance, using disk-backed streaming, expiry cleanup and authorization at download. Export handles are not permanent public links.

## Implementation and acceptance

[Local originals](../implemented/2026-09-05-repository-authoring-foundations.md#managed-originals-and-image-delivery) and the [logical media index](../implemented/2026-09-09-logical-media-index.md) provide the storage and atomic-authoring foundations. The complete target remains proposed; logical-path delivery, public-root policy, CodeAct, moves, exports and content conversion still require their owning implementation and acceptance.

Implement local media and workspace deduplication, then the logical index and public-root policy, CodeAct transport and selected-file saves, moves/browser interactions, and portable export. Remove redundant standalone MCP file-read/list/patch entrances when their behavior is covered; keep browser services and a narrow media transfer channel. Update the default repository template, root guidance, paired README/requirements and affected current-state records in the owning changes. Do not maintain a second agent CRUD architecture as a compatibility mode.

Provide a one-time existing-content conversion from a verified publication snapshot: preserve the actual public set and existing routes where possible, move other content into private, import Git binaries into local originals, map existing managed references to logical paths and repair links. Keep source version and original backups; coordinate content-format and application cutover with writes paused and rebuild the public snapshot. Git mirroring remains unchanged and is not an originals backup. Live execution of migration or deployment requires operator authorization.

Use targeted behavior tests plus required platform checks and one actual-client scenario. Prove workspace isolation with identical uploads, independent identities and authorization, publication changes in one workspace, guessed references, corruption and deletion isolation. Prove immutable history, media fetch without false deletion, index/text atomicity, conflicts and uncertain saves, revoked sessions, path/symlink escapes, public-only history exclusion, portable complete exports and bounded streaming. Exercise search, editing, media, save, move and export through real entrances. Native Linux storage and sandbox checks remain required; document-only or skipped Windows tests cannot stand in for them. Repeated model comparisons, a benchmark program, reviewer infrastructure, OSS, media playback, full disaster recovery and self-service tenancy are outside this delivery.
