# 邀请制成员

Date: 2026-08-27
Status: Proposed

## 问题

Poketto 的同一知识空间需要由所有者、受信任成员及各自的 AI 共同使用。[需求与架构](../implemented/2026-08-25-requirements-and-architecture.zh.md)已经允许受信任成员，却只规定发放 API Key，没有定义人类账户如何加入、离开或保留独立审计身份。

共享所有者账户或长期 API Key 会混淆操作归属，也无法单独撤销某位成员。开放注册又会改变个人自托管产品的信任边界。成员必须通过所有者发起的邀请加入指定工作空间。

## 提案

### 账户与 membership

- 人类账户是实例级身份；membership 把账户连接到一个工作空间，并赋予 `OWNER` 或 `MEMBER` 角色。一个账户可加入多个工作空间，每个空间的角色独立。
- 第一个账户通过一次性实例初始化流程成为实例管理员和默认工作空间的 `OWNER`。初始化完成后永久关闭该入口，不保留默认密码。
- 工作空间必须至少保留一个有效 `OWNER`。停用成员、离开工作空间或转移所有权不能移除最后一个 owner。
- 人类会话、AI API Key 和系统任务是不同 principal 类型。审计记录保存实际 principal，不把成员或 AI 的操作记在所有者名下。

本提案规定账户、会话和邀请的安全契约；具体页面样式不属于本提案。人类登录使用 Spring Security 管理的本地凭据和服务端会话，密码通过可升级的自适应哈希编码保存，绝不保存或记录明文。浏览器会话使用 `HttpOnly`、`Secure` 和合适的 `SameSite` cookie，所有状态修改请求启用 CSRF 防护。

### 邀请生命周期

- 只有 workspace `OWNER` 可以创建、列出和撤销该空间的邀请。邀请预先绑定工作空间和目标角色；v1 只允许邀请 `MEMBER`，不能通过邀请授予实例管理员。
- 邀请令牌由密码学安全随机数生成，只在创建响应中显示一次。数据库只保存令牌哈希、工作空间、角色、创建者、创建时间、到期时间、撤销时间和使用时间。
- 邀请默认七天过期，只能成功使用一次。过期、撤销、已使用和不存在的令牌向匿名调用者返回同一种失败语义，避免枚举。
- 接受邀请的人创建新账户或登录现有账户后加入目标工作空间。相同 membership 的重复接受是幂等成功；令牌不能用于加入其他工作空间或改变已有更高权限。
- 邀请链接由所有者自行传递。v1 不接入邮件或短信服务，也不把令牌写入应用日志、审计详情、Referer 或分析事件。

### 成员与密钥管理

- owner 可以停用 membership；停用立即阻止新的工作空间会话，并撤销该成员在该空间创建或持有的活动 API Key。其他工作空间的 membership 不受影响。
- AI API Key 绑定工作空间、创建者和 capability 集合。`MANAGE_KEYS`、成员邀请与成员停用默认只授予 owner；普通成员及其 AI 不得自行提升权限。
- 开放注册没有路由、API 或配置开关。增加开放注册需要新的提案，覆盖滥用、身份验证、合规和资源预算。

## 实现范围与依赖

本提案依赖[工作空间与租户边界](2026-08-27-workspace-tenancy.md)。它可以与内容仓基础并行实现，但人类可用的端到端验收还需要管理端提供初始化、登录、邀请和成员管理页面。

第一轮包括账户、membership、邀请、服务端会话、所有者初始化、密码登录、退出、邀请接受、成员停用、权限检查、审计归属和数据库集成测试。它不包括邮件发送、OAuth、社交登录、passkey、开放注册、自助工作空间创建或实例级运营后台。

## 考虑过的替代方案

**所有人共用所有者账户。** 实现最少，但无法独立撤销、追责或限制权限，也会迫使成员共享凭据。

**只给人类发 API Key。** 适合脚本和 AI，不适合浏览器会话、登录保护和成员生命周期。API Key 保留为机器凭据。

**开放注册后由 owner 审批。** 它扩大了匿名攻击面，并引入垃圾注册和身份验证问题。邀请制直接表达当前信任关系。

**邀请直接携带长期登录凭据。** 链接泄露会永久暴露账户。短期一次性邀请只用于建立账户或 membership，之后由正常凭据和会话接管。

## 验收条件

- 中英文需求文档同步纳入本地账户、工作空间 membership 和邀请制成员边界，同时继续明确不提供开放注册。
- 第一次初始化能建立唯一实例管理员与默认 workspace owner；初始化完成后不能再次使用同一入口。
- 邀请令牌具有足够随机性、只显示一次、仅以哈希存储，并在使用、撤销或过期后失效。
- 邀请只能建立其绑定 workspace 的 `MEMBER` membership；跨空间复用、权限提升和最后 owner 移除均被拒绝。
- 两个成员的页面操作、API Key 和审计身份彼此独立；停用一个 membership 不影响账户在其他空间的权限。
- 匿名错误不会泄露邀请是否存在；日志、指标和响应头不包含邀请令牌、密码或会话 secret。
- CSRF、会话固定、登录限流、密码哈希升级和权限拒绝路径具有针对性测试。
- PostgreSQL 集成测试、Spring Modulith 校验和 `./gradlew check` 通过。

## 风险

本地密码与会话使 Poketto 承担凭据保护责任。实现必须依赖 Spring Security 的成熟机制，不自行设计密码学；passkey 或外部身份提供方只有在真实需求出现后才增加。

实例级账户可以加入多个工作空间，因此账户停用与 membership 停用具有不同影响。管理端和错误信息必须明确操作对象，不能让 workspace owner 误以为自己能删除整个实例账户。
